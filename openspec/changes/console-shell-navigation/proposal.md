# Proposal: 控制台外壳导航反映真实层级（面包屑可点 + 显式返回）

## 背景

用户实机投诉（原话）：「进了员工详情不知道怎么返回，路径也不清晰」。此前顶栏面包屑
写死成「分组 · 控制台」，与真实路径无关——员工详情分区里看到的还是模块列表页的字样；
返回只能靠浏览器后退或侧栏重进。

本 change 把「我在哪、怎么回去」变成控制台壳层可观察的行为规格：

1. 面包屑显示当前页面的真实层级（分组 › 模块 › 员工详情 › 分区），中间层级可点击回跳；
2. 员工详情提供显式返回钮，窄屏也可见，不让人「只靠猜」找退路；
3. 分区写在查询串（`?zone=config`）还是路径段里，面包屑与页面标题必须给出同一个分区名。

## 变更内容

1. 顶栏面包屑由写死文案改为按当前路由解析出的层级生成：模块页一段、详情工作台两段、
   详情分区三段；带「上一层」语义的段渲染为可点链接。
2. 员工详情（层级 ≥2 的页面）在折叠钮旁增加显式返回钮；模块列表页不出现该钮。
3. 唯一 `<h1>` 在分区页显示分区中文名（工作台/配置/任务/运行/证据），
   查询串形制与路径段形制读数一致。

## 不改什么

- 不改路由表本身与深链参数语义（`?resume`、`?zone` 的取值集合不变）；
- 不改页面内部的分区条（tablist）——它自己的词表必须与顶栏一致，但不合并实现；
- 不动顶栏既有不变量：全页唯一 h1、右侧不放假控件；
- 不引入新的导航层级（如「租户」层），那是 IA 层面的另一件事。

## 依赖与风险

- 证据提交：`c3b83fbca2`（面包屑可点 + 返回钮）、`03dd183ba4`（查询串分区名）；
- 风险：分区名的词表在两处（顶栏与页内分区条）各自维护，改词必须两处同步，
  否则出现「顶栏叫配置、页内叫设置」的新不一致——验收场景按「同名」钉住。
