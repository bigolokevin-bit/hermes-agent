# console-navigation Specification

## Purpose

让控制台使用者在任何页面都能回答两个问题：**我在哪一层**、**我怎么回去**。
顶栏的层级指示必须来自真实路由，而不是写死的文案；深一层的页面必须给出看得见、
点得动的退路。

## ADDED Requirements

### Requirement: 面包屑反映真实层级

The system SHALL 按当前路由解析出的层级渲染面包屑：模块页显示分组一段；
员工详情工作台显示「分组 › 模块」两段；员工详情分区显示「分组 › 模块 › 员工详情」三段。
写死的、与路径无关的层级文案 SHALL NOT 出现。

#### Scenario: 进入某员工的配置分区
- **WHEN** 管理员从数字员工列表点开一位员工，再进入其「配置」分区
- **THEN** 面包屑依次为 分组、数字员工、员工详情 三段
- **AND** 页面唯一的标题显示该分区的中文名（如「配置」），而不是笼统的模块名

#### Scenario: 停留在模块列表页
- **WHEN** 管理员位于数字员工列表页
- **THEN** 面包屑只有分组一段，且该段不链向自己所在的页面

### Requirement: 面包屑上级可点回跳

The system SHALL 把面包屑中代表上一层级的段渲染为可点导航，点击后到达该层级的页面；
仅当前所在层级的末段不作为回跳目标。

#### Scenario: 从分区点「数字员工」
- **WHEN** 管理员在员工详情分区点击面包屑的「数字员工」段
- **THEN** 到达员工列表页

#### Scenario: 从分区点「员工详情」
- **WHEN** 管理员在员工详情分区点击面包屑的「员工详情」段
- **THEN** 到达该员工的工作台，且仍属于同一位员工

### Requirement: 详情页提供显式返回

The system SHALL 在存在上一层级的页面（详情类页面）提供一个显式返回控件，
其可访问名称说明它就是返回；模块列表页 SHALL NOT 出现该控件。

#### Scenario: 窄屏下的返回
- **WHEN** 管理员在 375 宽度的视口进入员工详情
- **THEN** 返回控件可见且可点，点击后回到进入前的页面

#### Scenario: 模块页没有多余的返回钮
- **WHEN** 管理员位于数字员工列表页
- **THEN** 顶栏不渲染返回控件

### Requirement: 分区形制不影响层级读数

The system SHALL 对同一分区的两种地址形制（路径段与查询串）给出相同的面包屑末段
与相同的页面标题；分区别名与未知取值 SHALL 归一到该员工工作台的层级读数，而不是留空。

#### Scenario: 查询串形制的配置分区
- **WHEN** 管理员打开形如「员工详情 + 查询串指定配置分区」的地址
- **THEN** 面包屑末段为「员工详情」、页面标题为「配置」
- **AND** 与路径段形制打开同一分区时的读数逐字一致

#### Scenario: 无法识别的分区取值
- **WHEN** 地址里的分区取值不在已知分区集合内
- **THEN** 顶栏退回该员工工作台的层级读数，不显示空标题、不显示英文原值
