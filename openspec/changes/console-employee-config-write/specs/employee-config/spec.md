# employee-config Specification

## Purpose

员工详情配置竖栏是管理员改这位员工的地方：能改的类给出可用的编辑控件并写明生效时机，
不能改的类如实说明没有写口；所有读数来自该员工自己的档案，失败与空集绝不互相冒充。

## ADDED Requirements

### Requirement: 配置分类如实标注可改性

The system SHALL 在配置竖栏为每个分类标注「可改」或「只读」，标签反映当前代次
该分类是否真的有写口，并与页面实际提供的控件一致。

#### Scenario: 有写口的分类
- **WHEN** 管理员查看配置竖栏中某分类，且该分类在当前代次有可用写口
- **THEN** 该分类标注「可改」，且点进去确实存在可提交的编辑控件

#### Scenario: 无写口的分类
- **WHEN** 某分类在当前代次只有读口
- **THEN** 该分类标注「只读」，页面不出现点了无效的伪控件

### Requirement: 模型与提示词接运行时真读数且身份正文可写

The system SHALL 在「模型与提示词」节展示该员工运行时档案的模型与提供方真读数，
并提供身份正文的编辑与保存；保存后的生效时机必须在界面写明。

#### Scenario: 档案已存在
- **WHEN** 管理员打开一位已有运行时档案的员工的「模型与提示词」节
- **THEN** 展示档案中的模型、提供方等真读数，档案标识可见
- **AND** 身份正文可在编辑区修改并保存，存在未保存改动时有明确提示，可放弃改动

#### Scenario: 保存后的生效范围
- **WHEN** 管理员保存身份正文成功
- **THEN** 界面写明「下一次新会话生效，已打开的会话仍用旧人格」

#### Scenario: 保存失败
- **WHEN** 保存请求失败
- **THEN** 原地显示失败原因（含可追踪编号，若上游回传），编辑内容不丢失

#### Scenario: 档案尚不存在
- **WHEN** 该员工还没有运行时档案
- **THEN** 本节如实说明「打开一次对话会自动创建」，不抢先建档、不显示猜测值

#### Scenario: 员工编号无法映射到档案
- **WHEN** 该员工的编号不能换算出可用的档案名
- **THEN** 本节不展示模型与人设，说明原因，且不出现可提交的写控件

### Requirement: 版本可作底稿但历史不可改写

The system SHALL 允许以任一历史版本为底稿起草并发布新版本；任何既有版本的内容
与时间线 SHALL NOT 因起草、发布或回退操作而改变。

#### Scenario: 以历史版为底稿
- **WHEN** 管理员在版本列表某行点击「以此为底稿」
- **THEN** 发布表单按那一版的真字段起草
- **AND** 界面写明「发布后生成新版本，历史版本不被改写」

#### Scenario: 撤销底稿
- **WHEN** 管理员在起草中改回「用最近一版」
- **THEN** 表单回到按最近一版起草的状态

#### Scenario: 底稿发布完成
- **WHEN** 以旧版为底稿的发布成功
- **THEN** 版本列表出现新编号的版本，被复制的旧版内容逐字未变

### Requirement: 工具组按员工档案逐个开关

The system SHALL 按该员工的运行时档案读取工具组清单（每组含启用/可用状态），
并允许逐组启用或停用；开关写入的是这位员工的档案，生效时机必须写明。

#### Scenario: 停用某工具组
- **WHEN** 管理员对某员工点击某工具组的「停用」并等待完成
- **THEN** 清单刷新后该组显示为未启用，且说明「下一次新会话生效（已打开的会话仍用旧工具面）」

#### Scenario: 开关失败
- **WHEN** 某组的开关请求失败
- **THEN** 卡片内原地报错并点名是哪个组，其余组状态不被改动

#### Scenario: 回包缺标识的行
- **WHEN** 清单某行没有可用的组名
- **THEN** 该行开关按钮禁用，系统不猜测组名发起写入

### Requirement: 技能按员工档案逐个开关

The system SHALL 按该员工的运行时档案读取技能清单（每条含启用与锁定状态），
未锁定的技能允许逐条启用/停用；锁定项 SHALL NOT 提供可用的开关。

#### Scenario: 启用一条技能
- **WHEN** 管理员对某员工的一条未锁定技能点击「启用」
- **THEN** 清单刷新后该技能显示为已启用，并写明新会话生效

#### Scenario: 锁定项
- **WHEN** 清单某条技能带有锁定标记
- **THEN** 该行显示「已锁定」，开关不可用

### Requirement: 空集与读失败不得互相冒充

The system SHALL 在配置各节区分三种状态：有数据、上游确认的空集合、读取失败；
读取失败 SHALL NOT 被呈现为空集或 0。

#### Scenario: 上游返回空集合
- **WHEN** 某清单读口成功返回且集合为空
- **THEN** 界面写明这是真实的空（不是加载失败）

#### Scenario: 读口失败或无法解析
- **WHEN** 某清单读取失败或回包形制无法解析
- **THEN** 界面按失败呈现（原因 + 重试入口），不显示空清单、不显示 0
