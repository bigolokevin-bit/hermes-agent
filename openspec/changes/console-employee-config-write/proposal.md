# Proposal: 员工配置竖栏从只读转为可写

## 背景

用户反馈：员工详情的配置竖栏「只是把档案读出来给人看」，改姓名、调工具、退版本都
要在别的系统里做。此前的口径是「本代次没有按员工的写口」——但取证发现运行时档案
（profile）接口上本来就有：模型、身份正文、工具组、技能都能按员工作用域读写；
员工域与版本域也已有改名/迁移/授权/发版写口。缺的是把界面接上去，并把「哪些能改」
如实标出来。

本 change 覆盖 2026-11-26 已交付的四块配置写口：

1. 「模型与提示词」节接运行时档案真读数，身份正文（人设）可编辑保存；
2. 版本链新增「以此为底稿」：复制历史版本再发布新版本，历史不被改写；
3. 配置左栏逐类标注「可改/只读」，标签是**当前代次有没有写口**的实况；
4. 工具组与技能按该员工的运行时档案读清单、逐个启用/停用。

## 变更内容

1. 配置竖栏每类带真实写口状态标签，管理员不用逐节点进去试。
2. 模型与提示词节显示该员工运行时档案的模型与提供方真读数；身份正文可编辑，
   保存只影响新会话，已打开的会话沿用旧值，界面上写明。
3. 版本行提供「以此为底稿」入口：发布表单按那一版的真字段起草，发布产出新版本号，
   任何历史版本的内容与时间线不变。
4. 工具组清单来自该员工档案作用域的读口，每行可启用/停用，写入该员工档案；
   失败在卡片内原地报错并点名是哪个组。
5. 技能清单同样按员工档案读，锁定项不可操作。

## 不改什么

- 不做「回滚」写口——历史版本不可变是域侧语义，本面只做「复制旧版发新版」；
- 不改模型/提供方的选择权（那是运行时分配的，本页只读展示）；
- 不抢先为空员工创建运行时档案（建档仍归「打开对话」那条链）；
- MCP 清单仍是租户级，本代次没有按档案的 MCP 写口，界面上不假装有。

## 依赖与风险

- 前端证据：`cd5e687bed`（模型与提示词）、`bb341679f9`（以此为底稿）、
  `f49449bdba`（可改/只读标签）、`e07b9d68ff` + `648d109a5e`（工具组与技能按档案读写）；
- 配套代理白名单在 BFF 仓：`l7-ops@98288f5175`（按档案作用域的工具/技能读写路由放行）；
- 风险：档案接口回包形制多变（工具组曾按裸数组读，实际是带包装的对象，
  读法错误会**静默显示为空集**）——验收必须区分「真空」与「读不到」；
- 风险：写口生效时机是「新会话」，若界面不写明，管理员会以为改动丢失；
- 已知缺口：左栏「可改/只读」标签是 `f49449bdba` 时点的手写台账，模型/工具/技能
  接上写口后标签未同步（仍显示「只读」），列为本 change 的收尾任务。
