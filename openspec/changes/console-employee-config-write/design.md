# Design: 写口归属、生效时机与「不冒充」纪律

## 每类配置的写口归属

| 配置类 | 写口在哪一侧 | 生效时机 |
|---|---|---|
| 身份与组织、生命周期、权限与授权 | 员工域（经 BFF 受控写路由） | 立即，写口带版本校验 |
| 版本与变更 | 员工域「发布新版本」 | 新版本生效时间起 |
| 模型与提示词（身份正文） | 运行时档案（本员工 profile） | 新会话；已开会话沿用旧值 |
| 工具组、技能开关 | 运行时档案（profile 作用域） | 新会话；已开会话沿用旧工具面 |
| 提供方/模型选择 | 无写口（运行时分配） | 只读展示 |
| 知识、预算、MCP | 本代次无按员工写口 | 标「只读」 |

归属决定了界面语义：**能改的必须明说改了何时生效；不能改的必须写为什么没有写口**，
不允许出现「看着像能改、点了没反应」的控件。

## 版本链的不可变性

域侧没有、也不该有「原地回滚」写口：回滚若实现为改写历史版本，版本链就失去追溯价值。
因此「退回旧配置」的唯一形制是**复制旧版字段 → 发布新版本**：结果上当前生效配置回到
旧值，过程上留下完整链条。底稿入口打开的发布表单以选中版本起草，且界面必须写明
「发布后生成新版本，历史版本不被改写」，并提供撤销底稿回到「按最近一版起草」。

## 静默空集是本面最危险的失败模式

工具组读口回包曾被按错误形制解析（期望裸数组、实际带包装对象），界面显示为
「空清单」，读起来像「这个员工没有任何工具」——这是读法 bug 冒充了业务事实。
设计要求：**空态必须能区分「上游回包确实是空集合」与「我没读懂/没读到」**；
后者一律按失败呈现（可重试、带原因），绝不显示为 0 或空清单。

## 写口不可用时的降级

按员工作用域保存需要该员工有可映射的档案名；映射不出（员工编号不合法）时，
本节整体降级为「无法按员工保存」的说明，而不是把开关打到未知目标上。
每行控件同样：回包里缺标识的行，按钮禁用，不猜名字。

## 已知边界

- 「可改/只读」标签是手填台账，与写口接线之间存在时点差（见 tasks 5.1）；
  规格要求标签反映**当前代次真实写口**，过期即违反本规格。
- 工具组/技能写 profile 作用域依赖 BFF 代理白名单（`l7-ops@98288f5175`），
  白名单外路由被拒时错误原样上屏，不在前端兜假成功。
