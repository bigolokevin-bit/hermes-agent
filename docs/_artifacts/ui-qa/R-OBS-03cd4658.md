## 4. 逐路由三选一归因

1. **`#/access`（台账 auth+anon 双侧都点名）→ ENV，其中有效登录态下的残留是上游未接线读口。**
   有效登录态只有 4 条 `404`，全部命中 `web/src/modules/access/access.ts:30-38` 写死的两组候选读口（`PEOPLE_ENDPOINTS = ["/agent-api/api/v1/user/list","/agent-api/api/v1/user/all"]`、`ROLE_ENDPOINTS = ["/agent-api/api/v1/role/list?page=1&limit=200","/agent-api/api/v1/roles?page=1&limit=200"]`，两组各 2 枚一次全试 → 天然 4 条）。页面渲染的是合规未接入态（testid `ac3-gap`，文案「角色与权限待核实：上游角色接口尚未接入本控制台」）。路由本身是兼容别名：`web/src/shell/routes.ts:266` `{ hash:'#/access', … kind:'compat-module', visible:false, to:'#/identity?tab=roles' }`，实际落地 `/identity?tab=roles`。
2. **`#/capabilities?tab=channels` → ENV（过期登录态 reload 风暴）+ 上游未接线读口（404 四枚）。**

## 5. 为什么台账把 auth 面也算进 obs（机制，非缺陷判定）

台账 auth 面 `authStateFile` 指向 `~/.local/state/sekoi-ops/v4-auth-state.json`，该登录态 JWT 已过期（前件 R-OBS-6c4f3385 实测：`exp` 早于当前时刻约 14 小时）。因此台账的 "auth 面" 在网关侧与匿名面等价，并在 `#/capabilities?tab=channels` 上放大成 stale-token reload 风暴（§3.3）。`routesWithEnvOnlyConsoleErrors=51`（auth）/ 50（anon）说明其余全部路由都被正确判为 ENV-only；只有风暴/瞬时行混入的那几格被判 product。**这与产品码无关，属采集口径与登录态老化。**

## 7. 取证边界（如实声明）

1. 台账 `base` 是 `http://127.0.0.1:9122`，与本派单要求的现网 8183 不一致；本件全部复现跑在现网 8183。
2. 台账 auth 面使用**已过期**的 `v4-auth-state.json`，故其 "auth" 与 "anon" 在网关侧等价；本件因此额外跑了三种态（有效 opsadmin 态 / 匿名态 / 台账过期态）以区分「真实登录态下的信号」与「老化态造成的噪声」。
3. 台账不落逐路由 console 原文（无 `consoleErrorSample`），因此**台账那 1~N 行的字节级原文不可得**；§3 全部为我在现网的实测原文。
4. `ENV_NOISE_RE` 只匹配 Chrome 的 `401 (Unauthorized)` / `404 (Not Found)` 两种 reason-phrase，且在 `slice(0,160)` 之后再判：403/500/`net::ERR_*` 类文案、以及被截断的长文本都会漏判为 product。本件 24 次采样未产生此类行。
5. `requestfailed` 不计入 obs 计数（`shots.mjs` 只数 console 与 pageerror），因此 §3.3 中数千条 `net::ERR_ABORTED` 本身不直接进 obs，只是风暴的量级证据。
6. 本件代次一致（台账与现网同为 `index-Chru2g4H.js`），无代次漂移；但单次采样存在运行时间戳/请求编号等运行时值差异，不可逐字节复算。
7. `#/capabilities?tab=channels` 四枚 404 读口的 `文件:行` 未能从 capabilities 非测试源码直接 grep 命中（见 §4.2），该项以「上游未接线读口」定性而不给行号。
8. 「24 次采样无一条非 401/404 原文」这一断言的依据是：三面 SUMMARY 的 `texts` 去重清单各只含一句、`productTexts=[]` 四面全空、以及逐条目视（`sed` 首 14 行）。中途一次用 2 空格前缀写的 `grep -h '^  \['` 交叉核对**无效**（脚本 console 行真实前缀是 4 空格 `    [n] `，该 grep 命中 0 属假阴性），不作为证据引用。

## 8. 建议（不改码，供上游拍板）

1. 台账 `base` 与派单口径统一到现网（或至少双份记录 base），避免「要求现网、实际本地」的长期错位。
2. 台账 auth 面换用有效登录态，或直接把 auth 面的过期态标记为 `login-state-expired` 并停止据此判 obs —— 本件的 4840 行格完全是老化态产物。
3. `ENV_NOISE_RE` 扩展识别 `net::ERR_*` 与裸状态码（含 403/500），并把 product 计数分列 `console` / `pageerror` 两类，避免瞬时行污染单一路由名下的红灯。
4. 台账逐路由落盘原文（首行 + 来源 URL + 状态），否则每代归因都必须外部重跑才能拿到原文。
5. 参数化路由（`:employeeId`）在 crawl 前做真实 id 替换，或在索引里显式标注「占位 id，无实体，fallback 态」，避免这类必然 404 长期占据 obs 名单。
