## 5. 结论（三选一）

**ENV 401/404 — 网关侧登录态与未接入读口产生的噪声，非产品码、非上游业务错。**

推理链：
1. 现网同法重走该路由，product 计数为 0，且 4 条噪声逐条命中 `ENV_NOISE_RE`（404 Not Found），与台账 `ceAuthority="login-state"`、`routesWithEnvOnlyConsoleErrors=51` 的定性一致。
2. 产品码路径已排除：`git grep -n "console\.error" -- web/src` 无匹配（应用自身不打 console.error）；`pageerror` 在两遍现网复现里均为空，即没有未捕获异常。
3. 上游业务错不成立：四条 404 全部是 `?limit=50` 的通用列表读口在网关未注册/未接入，属环境接线缺失，与 `R173-channels-ce.md` 判 (B) 不可修＝ENV/上游同一口径；上游业务失败会以 2xx + 专态呈现（本拍 approvals/audit 的「该字段未返回」即此类），不会变成 console error。
4. 那 1 条为何仍被记成 product：`consoleErrorsObservedByShots` 取的是「路由条数」，只要某条 console 文本不含 `401 (Unauthorized)`/`404 (Not Found)` 字样就计 1。台账 base（127.0.0.1:9122）实测存在 `net::ERR_ABORTED`（重试中断）形态的 `Failed to load resource` 行，其文本不含 401/404，必然漏过 `ENV_NOISE_RE` 而被归为 product。台账不落逐行原文，因此无法给出该条的字节级原文与首个堆栈——**这是本次归因的边界，不是结论的例外**。
